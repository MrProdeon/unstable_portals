# 🌀 Портальная лаборатория

Веб-приложение для смотрителя лаборатории, где открываются магические порталы.
Показывает список порталов, считает риск, рекомендует действие и позволяет
принять решение: стабилизировать, закрыть, отправить наблюдателя или пометить
портал «под вопросом». Все действия пишутся в журнал.

**Стек:** Python 3.12, Django 5.2, PostgreSQL 16, Docker Compose.

## Запуск

Нужны только Docker и Docker Compose.

```bash
# 1. Файл настроек
cp .env.example .env

# 2. Сборка и запуск (миграции применяются автоматически при старте)
docker compose up --build

# 3. Администратор (в другом терминале)
docker compose exec web python manage.py createsuperuser

# 4. Демонстрационные порталы (необязательно)
docker compose exec web python manage.py seed_portals
```

Приложение: http://localhost:8000/
Админка: http://localhost:8000/admin/

Остановка: `docker compose down` (данные сохраняются).
Полный сброс с удалением базы: `docker compose down -v`.

## Страницы

| Адрес | Что там |
|---|---|
| `/` | сводка, приоритетные порталы, список всех порталов |
| `/portals/<id>/` | карточка: параметры, рекомендация, действия, риск, журнал и история портала |
| `/log/` | общий журнал событий |
| `/admin/` | создание и редактирование порталов |

## Как считается риск

```
Риск (0–100) = 0.4 × (100 − Стабильность) + 0.3 × Энергия + 0.3 × Фактор времени
```

Фактор времени: 0, если срок не задан или осталось 72 ч и больше; 100, если срок
истёк; между ними растёт линейно. Уровни: до 30 — низкий, 30–59 — средний,
60 и выше — **критический**. У закрытого портала риск не считается.

Параметры формулы лежат в начале `portals/services.py`.

## Рекомендации

Правила проверяются сверху вниз, срабатывает первое подходящее:

1. Портал закрыт: действий не требуется.
2. Срок схлопывания истёк: закрыть.
3. Критический риск и осталось меньше 6 ч: закрыть.
4. Критический риск: стабилизировать.
5. Средний риск и внутри есть существа: отправить наблюдателя.
6. Средний риск, существ нет: пометить «под вопросом».
7. Низкий риск: оставить открытым.

## Действия и запреты

| Действие | Эффект | Запрещено, если |
|---|---|---|
| Стабилизировать | стабильность +25, энергия −15, срок схлопывания +24 ч | портал закрыт, схлопнулся или уже стабилен на 100 |
| Закрыть | статус «Закрыт» | портал закрыт. Если внутри есть существа, нужно подтверждение галочкой |
| Отправить наблюдателя | выводит до 3 существ | портал закрыт или схлопнулся, **риск критический** |
| Пометить «под вопросом» | ставит отметку | портал закрыт или уже помечен |
| Снять отметку | убирает отметку | портал закрыт или отметки нет |

Недоступные кнопки серые, причина написана под ними. Их можно нажать: сервер
откажет, покажет сообщение и запишет отклонённую попытку в журнал.
Правила находятся в `portals/rules.py`, эффекты — в `portals/actions.py`.

## Журнал и история

- **Журнал событий** (`/log/`): каждое действие (выполненное или отклонённое):
  что произошло, с каким порталом и когда.
- **История портала** (на карточке): любые изменения полей, в том числе из админки.

## Как проверить обязательные состояния

Сначала `docker compose exec web python manage.py seed_portals`.

1. **Пустой список.** `docker compose exec web python manage.py seed_portals --clear`,
   затем откройте `/`. Появится сообщение «Порталов пока нет», сводка покажет нули.
   Вернуть данные: `seed_portals`.
2. **Критический риск.** «Багровая трещина» и «Нестабильный разлом» имеют критический
   риск, красную отметку и счётчик «Критичных» в сводке.
3. **Запрещённое действие.** Откройте «Старый колодец» (закрыт) и нажмите
   «Стабилизировать»: отказ с причиной. В «Багровой трещине» нажмите «Отправить наблюдателя»
   (критический риск) и «Закрыть портал» без галочки (предупреждение про существ).
4. **Изменение риска после стабилизации.** В «Нестабильном разломе» нажмите
   «Стабилизировать»: в сообщении будет «Риск: 68 → 44 (Критический → Средний)»,
   а в истории портала появятся изменения стабильности, энергии и срока.
5. **Журнал после нескольких операций.** Выполните 4–5 действий, в том числе
   запрещённые, и откройте `/log/`.

## Частые проблемы

- **Не пускает в админку.** Проверьте пользователя:
  `docker compose run --rm web python manage.py changepassword <логин>`.
- **Порт 8000 занят.** Измените `"8000:8000"` в `docker-compose.yml`.
- **Время в UTC.** Для своего пояса измените `TIME_ZONE` в `config/settings.py`,
  например на `"Europe/Berlin"`.
